01 / question

Not a leaderboard

Frontier LLM papers arrive as bundles: a new attention mechanism, a routing rule, a memory layout, a kernel, and a training recipe. At production scale these choices are entangled. This repository shrinks the systems until individual choices can be read in one sitting, changed in one place, and trained on the same corpus.

Working question. Which architectural ideas train cleanly at toy scale, what does each one cost, and what does a controlled ablation actually let us conclude?

All models predict the next character in Tiny Shakespeare. The goal is not good Shakespeare. It is a durable experimental habit: make one change, preserve the evidence, compare only the runs that answer one question, and say no more than the evidence supports.

02 / method

One ordinary decoder, then one changed assumption

The dense control is a compact decoder with token embeddings, RMSNorm, causal attention, RoPE, optional grouped-query attention, QK-Norm, SwiGLU, residual additions, and tied output embeddings.

characters -> integer ids -> token embedding -> [RMSNorm -> token mixer -> +] -> [RMSNorm -> channel mixer -> +] x N -> RMSNorm -> tied LM head -> next-character logits token mixer: mixes information across positions channel mixer: transforms features within one position

That division is the organizing principle of the lab. Kimi changes channel routing and then the token mixer. GLM changes token selection while holding its channel mixer fixed. DeepSeek V4 changes how old context is represented, then changes only its channel mixer.

03 / architectures

Four ways to spend compute

Dense / Qwen-style control

Full causal attention reads every earlier token. SwiGLU transforms every token through one dense channel mixer. This is the control, not a weak baseline: it includes the normal modern decoder details needed to make later changes legible.

Kimi-style: recurrent memory and latent routing

Kimi step 1 replaces dense SwiGLU with a latent-space mixture of experts: tokens are compressed, routed to a small top-k expert set plus a shared expert, then expanded back to the residual width. Step 2 changes the token mixer. Kimi Delta Attention maintains a causal recurrent state and writes only the current prediction error. Gated MLA keeps a full-attention slot with a compact K/V latent. AttnRes can then read useful earlier states across depth.

residual stream |-- full causal attention -----------| all_full control |-- KDA recurrent delta state -------| hybrid schedules |-- Gated MLA compact K/V latent ----| +-> residual add -> LatentMoE -> residual add -> optional AttnRes

GLM-style: select, then read

Dense attention scores all causal positions and reads all of them. The GLM toy inserts a learned indexer: it scores causal positions, keeps top-k, and runs ordinary attention over only the selected K/V vectors. Its first layer remains dense SwiGLU; later layers use sigmoid-routed experts and a shared expert. The dense-attention GLM control keeps this channel mixer unchanged.

stream -> index query/key -> causal index scores -> top-k selected positions | stream -> ordinary Q/K/V -----------------------+-> gather selected K/V -> softmax read -> update

DeepSeek V4-style: exact nearby context, compressed old context

The V4 toy partitions history into local raw K/V, boundary raw K/V, and learned compressed entries for completed old chunks. The boundary exists so every past token is represented exactly once: no dropped position and no duplicate read. The optional mixed MoE uses static token-ID hash routing in the first layer, then learned routing in later layers.

old completed chunks -> learned compressed memory --\ partial boundary -----> raw K/V -----------------+-> old-context read --\ recent local window --> raw K/V ----------------------------------------+-> summed update

04 / experiments

Comparisons are pairs, not a ranking

Architectures naturally carry different parameter and active-compute profiles. A global winner table would be misleading. The valid comparison is the closest pair that changes one component.

QuestionHold fixedChange
Does Kimi hybrid attention help?Kimi MoE, width/depth, seed, data, optimizer, AttnRes offall_full vs 1L1F
Is the GLM selector the bottleneck?Dense-prefix routed MoE, seed, data, width/depth, optimizerDSA vs dense attention
Does V4 mixed MoE help?Local-compressed attention, seed, data, width/depth, optimizerDense SwiGLU vs hash-then-routed MoE

Interpretation rule. First check corpus fingerprint, seed, context length, optimizer, steps, and device. Then check parameter count and wall time. Only then compare validation curves. Samples are qualitative supporting evidence, never the primary metric.

06 / learnings

Small models still tell useful truths

  1. The dense decoder is hard to displace. It is the right control because it is already a strong, understandable system—not an intentionally weak baseline.
  2. Hybrid Kimi token mixing can learn better here, but not cheaply. The recurrent implementation changes loss and runtime together. Both measurements belong to the result.
  3. The current GLM failure is localized. Holding its corrected MoE fixed and changing only the token mixer makes DSA the likely bottleneck in this exact toy setting.
  4. V4-style routing is promising but not settled. Mixed MoE improves one seeded run, but its extra parameters and runtime prevent a cost-adjusted claim.
  5. Negative results are productively specific. “This DSA implementation did not help at 64 tokens” is a better outcome than a vague architecture ranking.

What this does not claim. These are not Qwen, Kimi, GLM, or DeepSeek reproductions. There are no fused kernels, production caches, distributed routing, BPE tokenization, long-context throughput measurements, or multi-seed scaling conclusions. Those omissions are deliberate: this lab teaches the data flow before the systems engineering.
